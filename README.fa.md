# بینش

> بازی حدس کلمه. ببین دوستانت واقعاً چقدر تو رو می‌شناسن.

هر دور یک نفر **سوژه** میشه. بقیه **حدس‌زننده** هستن و باید بفهمن که از بین دو کلمه تصادفی، سوژه کدوم رو ترجیح میده. هر حدس درست یک امتیاز. وقتی همه یک دور سوژه شدن، کسی که بیشترین امتیاز رو گرفته برنده میشه.

**[English — Read this in English](README.md)**

## چطور بازی کنیم

۱. **تنظیمات** — ۲ تا ۸ بازیکن اضافه کن، اسمشون رو بذار، و یک فهرست کلمه (انگلیسی یا فارسی) انتخاب کن.

۲. **انتخاب سوژه** — انتخاب کن که این دور، بقیه ذهن کی رو می‌خونن.

۳. **بازی** — سوژه از صفحه نگاهش رو بر می‌گردونه. دو کلمه نشون داده میشه. حدس‌زننده فعال هر دو کلمه رو بلند می‌خونه و از سوژه می‌پرسه کدوم رو ترجیح میده. اگه درست بود ✓، اگه غلط بود ✗ بزن. با 🔀 یک جفت کلمه جدید بیار.

۴. **پایان جلسه** — ببین کی سوژه رو بهتر می‌شناخت. سوژه بعدی رو انتخاب کن، یا وقتی همه یک دور سوژه شدن برو سراغ نتایج نهایی.

۵. **نتایج نهایی** — رتبه‌بندی نهایی رو ببین. با همون گروه دوباره بازی کن، یا بازیکن‌ها رو عوض کن.

هر بازیکن یک رنگ ثابت داره (بازیکن ۱ قرمز، ۲ آبی، ۳ سبز، ۴ زرد، ۵ بنفش، ۶ نارنجی، ۷ صورتی، ۸ فیروزه‌ای) که در کاشی‌های سوژه و حدس‌زننده صفحه بازی نشون داده میشه تا یک نگاه بفهمی کی کیه. کاشی‌های انتخاب سوژه هم یک نوار رنگی و ته‌رنگ ملایم به همون رنگ دارن.

## چطور اجرا کنیم

بینش فقط HTML + CSS + JS ساده‌ست. بدون بیلد، بدون وابستگی برای خود اپ.

### وب

هر هاست استاتیکی جواب میده:

```bash
python3 -m http.server 8000
# یا
npx serve .
```

بعد <http://localhost:8000/> رو باز کن. GitHub Pages، Netlify، Cloudflare Pages و Vercel همگی به همین شکل کار می‌کنن.

### اندروید (APK دیباگ)

اپ اندروید با Capacitor ساخته میشه. برای بیلد محلی به Node.js ۲۰ و Java ۲۱ JDK (برای Gradle) نیاز داری.

```bash
npm install
npm run prepare:www        # کپی فایل‌ها به www/، به‌روزرسانی نام کش sw
npx cap add android
npm run android:icons      # ساخت آیکون‌های لانچر از icons/
npx cap sync android
cd android && ./gradlew assembleDebug
```

فایل APK در `android/app/build/outputs/apk/debug/app-debug.apk` ساخته میشه. برای اینکه بتونی اون رو به‌عنوان آپدیت روی بیلد قبلی نصب کنی، باید با یک keystore ثابت امضا بشه — [`docs/APK_SIGNING.md`](docs/APK_SIGNING.md) رو ببین.

ریلیز‌ها به‌طور خودکار توسط GitHub Actions در `.github/workflows/build.yml` ساخته میشن و در صفحه Releases گیت‌هاب آپلود میشن. همین workflow فایل HTML تک‌فایلی رو هم می‌سازه و کنار APK به ریلیز ضمیمه می‌کنه.

### بیلد تک‌فایلی

برای ساخت یک فایل HTML مستقل (که از `file://` بدون سرور اجرا بشه):

```bash
npm install
npm run build:single
```

خروجی `dist/insight.html` هست. تمام CSS، JS و داده‌های ترجمه داخلش اینلاین شده، و همون فایلیه که با هر ریلیز گیت‌هاب منتشر میشه.

## زبان‌ها

- English (پیش‌فرض)
- فارسی — راست‌چین خودکار

تغییر زبان در نوار بالاست. فهرست کلمه خودش با زبان فعلی هماهنگ میشه. زبان و آخرین گروه اسم بازیکن‌ها در بازدیدهای بعدی حفظ میشن.

## اضافه کردن کلمه

`data/words.js` رو ویرایش کن و به آرایه `en` یا `fa` اضافه کن. طول دو فهرست رو تقریباً یکسان نگه‌دار تا هیچ زبانی کش نیاد.

## اضافه کردن زبان جدید

۱. `i18n/<code>.json` رو با همین ساختار `en.json` بساز.

۲. کد زبان رو به لیست زبان‌ها در `js/main.js` و `js/i18n.js` اضافه کن.

۳. یک فهرست کلمه متناظر به `data/words.js` اضافه کن (یا یک فهرست موجود رو به‌عنوان fallback انتخاب کن).

## نسخه‌گذاری

نسخه اصلی در `package.json` هست. workflow گیت‌هاب اکشنز اون رو می‌خونه، در بیلد اندروید قرار میده، و ازش برای به‌روزرسانی نام کش service worker استفاده می‌کنه. تگ‌های ریلیز باید با این نسخه یکسان باشن.
